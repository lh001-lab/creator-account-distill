# 怎样从逐条笔记形成方法库

## 每条先回答具体问题

- 这条实际是教学、案例、故事还是推广？作者明确提出的方法叫什么？
- 他改变了内容的哪个部分：目标人群、选题、人物、关系、场景、动作、道具、语言、节奏、声音、揭示顺序，还是转化安排？
- 明确列出的分类是什么？标题数字、口播与屏幕可能不一致，逐一核对并标记差异。
- 原片用什么案例解释？案例中的动作、机位、声音、铺垫和结果怎样配合？
- 方法在什么条件下可用，给什么人看，解决什么问题？哪些条件是作者说的，哪些是本次归纳？
- 用户如何拍：谁出镜、第一镜拍什么、中间需要什么变化、何时交代结果、需什么证据？不要只写加强反差一类空建议。

阅读长批次时按稳定 ID 整理；音频段落带时间，必要时添加证据位置。每完成一批更新笔记，不到最后才凭记忆补写。

## 去重但不丢作品

建立三层：作者原词 → 实际机制 → 可执行拍摄动作。近义词或同一案例被反复命名，合并到共同机制，保留各视频的分类、变化、附加条件和原链接。反过来，同名方法若清单不同，也需分别记录。

例如改变道具是一项创意变量；把它叫抽象、荒诞还是反常，不会自动产生三种独立机制。先建立观众判断再揭示事实，才是另一层的观看顺序设计。这只是分析示例，不要求每个博主都被套进同一理论。

## 同时拆作者自己的表达

区分两件事：他教别人怎样做，以及他自己怎样持续生产内容。检查首镜、问题提出、案例对照、论证转场、命名、分类、字幕、旁白、画面布局、固定口头语、结尾引导。观察重复栏目是否有固定模板，分析哪部分可复用、哪部分依赖作者的素材与表现力。

不要把作者口中的连夜逐帧拆解等表述，当作你已经证实的研究过程。增长数字也不能证明某一创意变量导致增长；对照案例不等于控制实验。

## 迁移到用户业务

仅在用户要求或当前任务明确需要时加应用方案。明确目标客户、业务价值和现有素材；用真实任务、实际选择、交付标准和可验证结果形成脚本。示例没有执行时标为试拍或模拟，不编造客户经历和效果。

优先给出最容易获得真实素材的少量形式；无需凑固定数量的方法、脚本或发布比例。讲知识的账号也可有情绪价值，展示情绪的账号也可能需要业务证据，按其目标判断。

## 有限画面的结论边界

ASR 读完和关键帧抽看可支持多数口播教学的归纳，但不一定支持精确的剪辑节奏、微表情或声音设计结论。遇到此类分析，实际查看或听取相关完整片段；工具没有可听取/播放能力时记录限制，不虚构感官观察。图表和提示词看不清时保留意译或明确未辨认，不自称逐字还原。
