# 交付和故障处理

## 长报告

适合的组织顺序是研究范围与主要发现、去重后的方法与适用条件、作者自己的栏目结构、按需定制的拍摄流程、逐条索引。根据材料调整，不为固定页数填充。保留每条记录，即使它只是案例或与前作重复。

`export_report.py` 只用 Python 标准库，生成离线可搜索 HTML，转义标题、笔记和链接内容，不依赖外部脚本或字体。默认显示审核范围、待处理项和每条记录，不自动填补缺失笔记。验证中文、长标题、来源链接、搜索过滤与跨条目 ID；可通过浏览器或现有文件预览检查。

Word/PDF/表格按用户指定，并调用可用的对应 Skill。不要把本次报告的内容、账号名、日期、固定158条数量或文件路径硬编码到新账号的交付。

## 中文 Word 预览

上次环境中，DOCX 字体配置本身正确，但 bundled LibreOffice 未加载系统中文字体，导致预览中文为空。不要只检查文档 XML 或认为导出成功就交付。

出现这个具体问题时：检查实际字体目录和渲染器日志；为本次渲染创建任务内 fontconfig XML，列出本机真实字体目录、可写缓存，再用 `FONTCONFIG_FILE` 指向它运行渲染器。比如 macOS 可包含 `/System/Library/Fonts`、`/Library/Fonts`，以及本机存在的 AssetsV2 字体目录。不可将这些路径当作所有系统通用配置，也不修改全局字体配置。将正文 CJK 字体设置为实际存在的字体，删除默认标题装饰线，渲染后看页面。

用标题的 `page_break_before` 控制分页，避免文末追加分页符段落溢出成空白页。长条目不要按固定每页数量强塞；以实际渲染为准。

## 已知处理陷阱

- FFmpeg image2 把输出路径里的 `%` 解释为序列格式，标题含百分数会只生成一帧后失败。配套脚本以内容哈希建目录，并在序列目录中将 `%` 转义为 `%%`，仅保留 `%05d.jpg` 为序列占位。
- 音频转写和抽帧分别记录状态。抽帧失败不能让完成的转写消失；跳过转写时仍检查本次需要的抽帧间隔与实际帧数。
- 媒体类型取自源信息与实际文件，不能把 duration 为 null 的视频写成图文。
- 缩略图用于找位置和检查布局；精细文字要看对应原始帧。OCR 结果按框的垂直位置读；Apple Vision 的 y 从下方算起，因此阅读顺序通常按 y 降序。
- 标题不能作为唯一键，下载器的数据表也不能作为唯一库存。清单与媒体及处理状态需要交叉核对。
- 工具缓存完成不等于人已核对。不要自动把 `human_verified` 设为 true。

## 阻碍与交付措辞

平台登录失效、权限不足或接口限制时，先查当前已取得资料和独立可做的整理。不要反复绕过验证；需要用户补充主页或登录时明确缺的是什么。可交付部分研究，但必须列覆盖数、缺失作品及原因，不能改称全量完成。

准确措辞示例：已完整转写并逐条阅读X条视频，抽查关键画面，Y条仍待补齐。只有实际逐帧/完整播放核对时才使用相应说法。
